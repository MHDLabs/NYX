# NYX

> یک پلتفرم ارتباطی سبک و ترمینال‌محور برای توسعه‌دهندگان و کاربران فنی.

NYX یک پروژه متن‌باز و آزمایشی است که هدف آن ساخت یک سیستم پیام‌رسانی ساده با محوریت ترمینال است.

ایده NYX چیزی بین **IRC، Signal و پیام‌رسان‌های مدرن** است؛ با تمرکز جدی روی استفاده در ترمینال، سادگی، حریم خصوصی و تجربه مناسب برای کاربران فنی و توسعه‌دهندگان.

این پروژه عمداً قرار است کوچک و قابل‌مدیریت باقی بماند. هدف NYX ساخت یک پلتفرم عظیم با هر قابلیت قابل تصور نیست.

## مسیر فعلی پروژه

مسیر فعلی NYX بر چند ایده اصلی متمرکز است:

* تجربه کاربری مبتنی بر ترمینال
* معماری سبک
* کلاینت نوشته‌شده با Rust
* پروتکل سرور مستقل از زبان برنامه‌نویسی
* پیام‌رسانی خصوصی و امن
* مدل ساده سرور و فدراسیون در صورت امکان
* مناسب برای ارتباطات و گردش‌کارهای توسعه‌دهندگان
* وابستگی‌های حداقلی و پرهیز از پیچیدگی غیرضروری
* پروتکل قابل توسعه به‌جای وابستگی اکوسیستم به یک زبان خاص برای سرور

کلاینت قرار است با **Rust** نوشته شود؛ چون Rust می‌تواند پایه‌ای سریع، سبک، قابل‌حمل و مناسب برای یک برنامه ترمینالی فراهم کند.

سمت سرور عمداً به **یک زبان خاص** وابسته نیست. یک پیاده‌سازی سرور می‌تواند با PHP، Python، JavaScript/TypeScript، Rust یا هر زبان مناسب دیگری نوشته شود، به شرطی که از پروتکل NYX پیروی کند.

## ترمینال در اولویت

ترمینال در NYX صرفاً یک رابط کاربری دیگر نیست.

ترمینال رابط اصلی پروژه است.

کلاینت با این هدف طراحی می‌شود که کاربر بتواند ترمینال را باز کند، به یک سرور متصل شود، با دیگران ارتباط برقرار کند و برنامه را بدون نیاز به محیط دسکتاپ گرافیکی مدیریت کند.

جهت‌گیری TUI از بخش‌های موفق نمونه‌های قبلی NYX الهام می‌گیرد، اما معماری آزمایشی قبلی قرار نیست به همان شکل ادامه پیدا کند.

## پروتکل در اولویت

هدف NYX تعریف یک پروتکل شفاف بین کلاینت و سرور است، نه مجبور کردن همه به استفاده از یک پیاده‌سازی سرور یکسان.

در نتیجه، پیاده‌سازی‌های مختلف سرور می‌توانند در کنار یکدیگر وجود داشته باشند:

```text
             پروتکل NYX
                  │
       ┌──────────┼──────────┐
       │          │          │
      PHP       Python    JavaScript
       │          │          │
     Server     Server     Server
```

پروتکل، لایه مشترک میان این پیاده‌سازی‌هاست.

به این شکل می‌توان سرورهای مختلفی ساخت، بدون اینکه لازم باشد کلاینت برای هر زبان یا پیاده‌سازی تغییر کند.

## امنیت و حریم خصوصی

امنیت بخش مهمی از پروژه است؛ اما NYX ادعا نمی‌کند که امنیت کامل، ناشناس‌بودن کامل یا زیرساخت غیرقابل‌شکست ارائه می‌دهد.

پروژه ترجیح می‌دهد از روش‌های رمزنگاری شناخته‌شده و مرزهای امنیتی ساده و قابل‌درک استفاده کند، به‌جای اینکه رمزنگاری اختصاصی یا سیستم‌های بیش‌ازحد پیچیده ایجاد کند.

قابلیت‌هایی مانند رمزنگاری، احراز هویت هویت کاربران، اعتماد به سرور و مقابله با سوءاستفاده زمانی اضافه خواهند شد که بتوان آن‌ها را به‌صورت واقع‌بینانه طراحی و پیاده‌سازی کرد.

## قابلیت‌های اختیاری اکوسیستم

بعضی از ایده‌هایی که در طراحی‌های قبلی NYX وجود داشتند، عمداً جزو معماری اصلی فعلی نیستند.

برای مثال، سیستم شهرت، هوش مصنوعی، زیرساخت غیرمتمرکز یا قابلیت‌های تخصصی دیگر ممکن است در آینده به شکل **کاربر، سرویس، افزونه یا عضو پروتکل با نقش/تگ مشخص** وجود داشته باشند؛ نه اینکه به بخش اجباری کل سیستم تبدیل شوند.

هدف این است که هسته اصلی ارتباطی تا حد ممکن کوچک باقی بماند.

## نقشه راه

NYX در حال حاضر در مرحله **تحقیق و بازطراحی** قرار دارد.

هدف فعلی، عجله برای پیاده‌سازی نیست. ابتدا باید معماری، مرزهای پروتکل، رابط ترمینال و محدوده پروژه به شکل مشخص و منطقی تعریف شوند.

مسیر کلی توسعه به‌صورت زیر در نظر گرفته شده است:

```text
تحقیق و طراحی
       │
       ▼
تعریف پروتکل
       │
       ▼
کلاینت TUI با Rust
       │
       ▼

       │
       ▼
```

این نقشه راه عمداً انعطاف‌پذیر است. قابلیت‌ها تنها زمانی اضافه خواهند شد که هدف مشخصی داشته باشند و بتوان آن‌ها را بدون تبدیل پروژه به زیرساختی غیرضروری و پیچیده پیاده‌سازی کرد.

## وضعیت پروژه

**NYX در حال حاضر متوقف شده است.**

پروژه فعلاً متوقف می‌ماند تا طراحی فعلی بررسی شود و زمان و تمرکز روی پروژه‌های دیگر قرار بگیرد.

ممکن است توسعه پروژه برای مدت نسبتاً طولانی، حتی **تا یک سال یا بیشتر**، متوقف بماند.

بنابراین این مخزن نشان‌دهنده مسیر و مستندات فعلی پروژه است و به معنی توسعه فعال یا ادامه قطعی توسعه در آینده نزدیک نیست.

اگر توسعه دوباره آغاز شود، پیاده‌سازی بر اساس معماری ساده‌شده فعلی انجام خواهد شد و قرار نیست تمام قابلیت‌های نمونه‌های قبلی حفظ شوند.

## نمونه‌های قبلی

NYX در طول توسعه خود چندین نسخه و رویکرد معماری آزمایشی مختلف داشته است.

این نسخه‌ها برای آزمایش ایده‌ها مفید بودند، اما **پایه پیاده‌سازی فعلی پروژه محسوب نمی‌شوند**.

مسیر فعلی عمداً از یک معماری تمیزتر و کوچک‌تر شروع می‌شود و در عین حال از تجربه و نکات مفید نمونه‌های قبلی رابط ترمینال استفاده می‌کند.
